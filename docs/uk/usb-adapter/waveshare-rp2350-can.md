# Waveshare RP2350-CAN

Адаптер, який використовується під час розробки PROJECT YFA, побудований на платі Waveshare RP2350-CAN.

На ньому працює версія прошивки CANnectivity/Bridle для PROJECT YFA, яка надає Android-пристрою USB CAN-інтерфейс, сумісний із gs_usb.

## Поточна конфігурація CAN

Поточне застосування використовує **Classical CAN зі швидкістю 500 кбіт/с**, а не CAN FD. Тому конфігурація прошивки містить:

```text
CONFIG_CAN_FD_MODE=n
```

Зараз PROJECT YFA очікує, що адаптер повідомлятиме **тактову частоту CAN 8 МГц**. Android-транспорт налаштовує потрібні параметри 500 кбіт/с під час запуску сеансу зчитування.

Raw CAN і USB Пасивний UDS використовують режим listen-only. Активний UDS навмисно не використовує listen-only, оскільки для нього потрібно передавати діагностичні CAN-кадри.

Поточна USB-реалізація також вимагає апаратних часових міток CAN.

## USB-інтерфейс

Зараз адаптер визначається як:

```text
VID: 0x1209
PID: 0xCA01
```

PROJECT YFA використовує інтерфейс gs_usb 0, bulk IN endpoint **0x81** і bulk OUT endpoint **0x02** у поточній реалізації CANnectivity.

USB-з'єднання відкривається до початку зчитування, але параметри CAN і режим роботи налаштовуються під час запуску вибраного режиму зчитування.

## Модифікація буферів gs_usb для PROJECT YFA

Прошивка PROJECT YFA не використовує початкову схему зі спільним пулом буферів host frame gs_usb.

Під час дослідження стабільності Активного UDS було виявлено періодичну помилку: інтенсивний прийом CAN міг вичерпати спільний пул gs_usb саме тоді, коли USB bulk-OUT endpoint потребував буфер для нового кадру від хоста. Після цього bulk-OUT endpoint не міг повторно активуватися, і наступне передавання CAN з Android завершувалося тайм-аутом, хоча приймання CAN могло продовжуватися.

Щоб RX-трафік не міг позбавити TX-шлях буферів, прошивку змінено для використання **окремих пулів RX і TX**.

Наявний параметр залишено як пул приймання/помилок:

```text
CONFIG_USBD_GS_USB_POOL_SIZE=128
```

Для буферів передавання від USB-хоста додано окремий параметр:

```text
CONFIG_USBD_GS_USB_TX_POOL_SIZE=16
```

RX-пул використовується для CAN-кадрів, що передаються до USB-хоста. Окремий TX-пул використовується для кадрів, отриманих через USB bulk OUT. TX-буфер залишається пов'язаним із передаванням через TX FIFO прошивки, передавання CAN, TX echo та завершення USB IN, після чого повертається до TX-пулу.

Такий поділ важливий для Активного UDS у PROJECT YFA: безперервний прийом CAN-трафіку автомобіля більше не може використати буфери, зарезервовані для діагностичного передавання.

!!! note "Примітка"
    Збільшення початкового пулу до 128 покращило запас для приймання, але пізніша модифікація з розділеними пулами вирішує іншу проблему — ізоляцію TX-шляху від навантаження на RX-буфери.

## Runtime-керування USER LED у PROJECT YFA

Прошивка PROJECT YFA додає runtime-керування USER LED поверх звичайного автомата стану/активності LED у CANnectivity.

Використовуються два vendor-запити PROJECT YFA:

```text
0xF1  GET settings
0xF2  SET settings
```

Налаштування — це 32-бітне little-endian поле прапорців:

```text
bit 0 = примусово вимкнути USER LED
```

Для `0xF2` PROJECT YFA надсилає чотирибайтовий payload:

```text
01 00 00 00  -> примусово вимкнути USER LED
00 00 00 00  -> звичайне керування LED прошивкою
```

Прапорець існує лише в RAM. Reset або втрата живлення повертає прошивку до звичайного керування LED. Постійність забезпечує Android-застосунок, який повторно застосовує збережене налаштування після наступного підключення.

Коли override увімкнений, індикація стану та RX/TX-активності, що використовує USER/state LED Waveshare, пригнічується без зміни роботи CAN або USB. Це перевірено тим самим gs_usb benchmark-навантаженням, яке використовувалося під час роботи над розділеними RX/TX буферами: benchmark успішно проходив і зі звичайним блиманням, і з вимкненим USER LED.

PROJECT YFA також використовує стандартний gs_usb-запит IDENTIFY для одного підтверджувального блимання, коли користувач вимикає опцію **Вимкнути індикатор USER** при підключеному адаптері.

## Підсумок конфігурації прошивки

Важливі поточні параметри PROJECT YFA:

```text
CONFIG_USBD_GS_USB_POOL_SIZE=128
CONFIG_USBD_GS_USB_TX_POOL_SIZE=16
CONFIG_CAN_FD_MODE=n
```

Параметр TX-пулу є модифікацією реалізації CANnectivity/Bridle gs_usb для PROJECT YFA, а не лише налаштуванням Android-програми.

## USB-транспорт Android

PROJECT YFA використовує синхронні операції Android `bulkTransfer()` для обміну gs_usb.

Це рішення замінило попередню реалізацію приймання через `UsbRequest/requestWait()` під час робіт над стабільністю Android. USB-менеджер підтримує безперервний шлях приймання під час активного зчитування та використовує bulk OUT endpoint, коли Активному UDS потрібно передавати CAN-кадри.

## Перевірка

Прошивку з розділеними пулами було протестовано під навантаженням у середовищі розробки PROJECT YFA. Тест із 60 циклами ПУСК/СТОП на Android завершив 689 переданих кадрів і приблизно 622 018 прийнятих USB transfers без помилок TX, втрат або пошкоджених transfers. Окремий тест у Windows завершив 21 000 переданих кадрів без помилок виділення буферів або постановки в чергу.

Ці показники описують перевірену збірку для розробки та корисні як орієнтир для регресійних тестів; вони не є загальною специфікацією продуктивності для кожного Android-пристрою або CAN-шини.

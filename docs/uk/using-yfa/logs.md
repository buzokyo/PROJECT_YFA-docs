# Журнали

PROJECT YFA може зберігати трафік зчитування у текстових журналах формату CL2000 і має вбудований екран **Журнали** для перегляду, пошуку, коментування, поширення, експорту та видалення записаних сеансів.

Спочатку виберіть кореневий каталог PROJECT YFA у **Налаштування → Запис → Каталог PROJECT YFA**.

## Структура каталогу PROJECT YFA

PROJECT YFA зберігає один постійний Android-дозвіл на вибране дерево документів і створює такі підкаталоги, коли вони вперше потрібні:

```text
PROJECT YFA/
├─ logs/
├─ debug/
├─ exports/
└─ metadata/
```

- **logs/** — сирі журнали зчитування `.TXT` у стилі CL2000;
- **debug/** — діагностичні журнали Bluetooth/USB/MQTT, коли ввімкнено налагоджувальне журналювання;
- **exports/** — декодовані CSV-файли, експортовані з журналів;
- **metadata/** — файли метаданих PROJECT YFA, зокрема `PROJECT_YFA_LOGS.json` і `PROJECT_YFA_VEHICLES.json`.

Вибір іншого каталогу PROJECT YFA змінює кореневе місце для всіх цих функцій.

## Запис журналу

Увімкніть **Журнал** у меню головного екрана перед запуском зчитування.

Після старту зчитування PROJECT YFA створює один незалежний файл `.TXT` для цього сеансу в каталозі **logs/**. Поточна реалізація не розбиває один сеанс на кілька файлів.

Якщо журналювання ввімкнене, але каталог PROJECT YFA ще не вибрано, застосунок може відкрити системний вибір каталогу Android перед продовженням зчитування.

Коли зупиняється сеанс, у якому вже записувалися дані, PROJECT YFA просить підтвердження, оскільки поточний файл журналу буде закрито.

## Інформація про автомобіль у метаданих журналу

PROJECT YFA відстежує дані автомобіля, які використовуються екраном Журнали.

Під час підключення та зчитування застосунок може визначити VIN і пробіг із підтримуваних CAN/UDS-джерел. Якщо потрібні значення не вдалося отримати автоматично, їх можна ввести або прочитати через діалог інформації про автомобіль, не перериваючи зчитування.

Наприкінці записаного сеансу PROJECT YFA може попросити підтвердити кінцевий пробіг перед збереженням остаточних метаданих журналу.

Відомі дані автомобіля зберігаються у `metadata/PROJECT_YFA_VEHICLES.json`, а метадані окремих журналів — у `metadata/PROJECT_YFA_LOGS.json`.

Метадані журналу містять ECU/мітку сеансу, час початку, тривалість, кількість записів, розмір файла, VIN, початковий і кінцевий пробіг та необов'язковий коментар користувача. Sidecar-файл є основним індексом метаданих журналів.

## Формат файла

Сирий журнал використовує знайому текстову структуру CL2000:

```text
# Logger type: PROJECT YFA
# HW rev: Android
# FW rev: <версія застосунку>
# Logger ID: PROJECT_YFA
...
# Bit-rate: 500000
Timestamp;Type;ID;Data
```

Формат мітки часу — `ddTHHmmssSSS`. Type зараз дорівнює `0`. CAN ID і payload записуються великими шістнадцятковими символами.

Ім'я файла має вигляд:

```text
YYYY-MM-DD_HH-mm-ss_ECU.TXT
```

### Зведені журнали ECUs

Під час зчитування з USB-вкладки **ECUs** у назві файла використовується мітка `ECUs`. Зведений Raw CAN-сеанс слухає всі отримані CAN-кадри для журналювання, тоді як декодування обмежується CAN ID, відомими базі PROJECT YFA.

Зведені Пасивний та Активний UDS записують відповідні діагностичні відповіді під тією самою міткою сеансу `ECUs`.

## Перегляд журналів

Відкрийте **Журнали** з меню застосунку.

Екран читає PROJECT YFA `.TXT` файли з **logs/** і поєднує їх із метаданими з **metadata/PROJECT_YFA_LOGS.json**. Новіші сеанси показуються першими та групуються за місяцями.

Картка журналу показує дату й час початку, розмір файла, кінцевий пробіг, пройдену відстань, тривалість, ECU/мітку сеансу та необов'язковий коментар.

## Пошук

Натисніть значок пошуку, щоб відфільтрувати сеанси. Пошук перевіряє ECU/мітку сеансу, дату й час, початковий або кінцевий пробіг, розраховану відстань та коментар.

## Коментарі

Відкрийте меню **⋮** журналу та виберіть **Edit comment**, щоб додати коротку нотатку.

Коментар зберігається у `metadata/PROJECT_YFA_LOGS.json`, а не всередині сирого `.TXT` файла. Він показується на картці журналу та бере участь у пошуку.

## Дії з журналом

**Edit comment** змінює sidecar-метадані.

**Export CSV** декодує підтримувані LIVE-відповіді UDS і записує CSV-файли в **exports/**.

**Share** відкриває системний Android-інтерфейс поширення для оригінального сирого журналу.

**Delete** просить підтвердження та видаляє сирий журнал.

## Експорт CSV

Експорт CSV використовує поточні визначення з вбудованого `signals.json`.

Для кожного UDS-запиту, для якого в журналі є декодовані LIVE-відповіді, створюється окремий CSV. Стовпці містять **Timestamp**, а далі — назви декодованих сигналів.

Імена експортованих файлів мають вигляд:

```text
<ім'я-журналу-без-TXT>_<UDS-request>.csv
```

Файли записуються в **exports/**, використовують UTF-8 і містять BOM.

!!! note "Примітка"
    Поточний CSV-експортер орієнтований на UDS-запити та декодує LIVE-визначення. Тому сирий журнал PROJECT YFA може бути корисним навіть тоді, коли з нього не створюється CSV.

## Усунення проблем із доступом

Якщо журнали раптово зникли зі списку, перевірте **Налаштування → Запис → Каталог PROJECT YFA** і Android-доступ до цього кореневого каталогу. Сирі файли залишаються у **logs/**.

Якщо постійний Android-дозвіл втрачено, екран Журнали може запропонувати вибрати каталог PROJECT YFA знову.

Налагоджувальні журнали адаптера зберігаються у **debug/**, а не разом із журналами зчитування.

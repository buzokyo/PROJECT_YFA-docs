# MQTT і Home Assistant

PROJECT YFA може публікувати декодовану live-телеметрію на MQTT broker і автоматично оголошувати ці сигнали в Home Assistant через MQTT Discovery.

Налаштуйте broker у **Налаштування → Підключення → MQTT broker**, а потім використовуйте перемикач **MQTT** на головному екрані для ввімкнення або вимкнення телеметрії.

## Підключення

PROJECT YFA використовує MQTT 5.

Тепер увімкнення MQTT і підключення до broker прив'язані до життєвого циклу сеансу зчитування:

- увімкнення **MQTT** на головному екрані лише дозволяє телеметрію, але не тримає з'єднання з broker відкритим, коли зчитування зупинене;
- коли MQTT увімкнений і починається сеанс зчитування, CANly відкриває MQTT-з'єднання;
- коли зчитування зупиняється, CANly за можливості публікує retained `offline` і від'єднується;
- якщо вимкнути MQTT під час зчитування, MQTT-транспорт зупиняється одразу;
- під час наступного сеансу зчитування підключення виконується автоматично, якщо MQTT залишається ввімкненим.

Під час запуску транспорту використовуються налаштовані host, port, необов'язкові username/password і параметр TLS. Коли TLS увімкнено, використовується стандартне сховище довіри платформи Android.

Для кожного підключення створюється client ID, що починається з:

```text
project-yfa-
```

З'єднання використовує keep-alive 30 секунд і clean start.

## Topics стану та доступності

Якщо налаштований base topic:

```text
project_yfa/vehicle
```

PROJECT YFA публікує в:

```text
project_yfa/vehicle/state
project_yfa/vehicle/availability
```

Повідомлення доступності мають значення `online` та `offline`. Вони retained і публікуються з QoS 1. PROJECT YFA також налаштовує retained Last Will зі значенням `offline`.

Коли MQTT-транспорт зупиняється після успішного підключення — наприклад, після завершення зчитування або вимкнення MQTT — CANly намагається опублікувати retained `offline` перед від'єднанням.

## Телеметрія стану

Snapshots стану — це JSON-об'єкти з номером послідовності, часовою інформацією snapshot, об'єктом `values` та об'єктом `units`.

Спрощений приклад:

```json
{
  "sequence": 123,
  "created_at_ms": 0,
  "newest_measurement_at_ms": 0,
  "values": {
    "signal-id": 42.0
  },
  "units": {
    "signal-id": "°C"
  }
}
```

Публікуються лише snapshots, що містять значення. Повідомлення стану retained і використовують QoS 1.

Публікація MQTT налаштовується окремо для кожного сигналу в редакторі **Сигнали**. Публікуватися можуть лише сигнали, вибрані значком MQTT/хмари надсилання. Сигнал може бути лише MQTT-сигналом: його не обов'язково показувати в LIVE або вибирати для PLOT.

Значення телеметрії надходять із декодованих даних зчитування CANly, тому кінцевий набір також залежить від ECU, режиму зчитування та даних, які реально доступні під час сеансу.

## MQTT Discovery для Home Assistant

Для кожного вибраного для MQTT сигналу телеметрії, який з'явився після встановлення з'єднання, CANly публікує retained конфігурацію сенсора Home Assistant.

Discovery topics мають вигляд:

```text
homeassistant/sensor/project_yfa_<object-id>/config
```

Усі знайдені сенсори групуються в один пристрій Home Assistant із назвою **PROJECT YFA Vehicle**, manufacturer **PROJECT YFA** і model **Vehicle telemetry**.

Discovery-конфігурації використовують topics стану та доступності PROJECT YFA. Одиниці сигналів додаються, якщо вони визначені. Числові недискретні вимірювання отримують state class `measurement`, а рекомендована точність відображення передається, якщо вона задана у визначенні сигналу.

Якщо раніше оголошений сигнал потім знято з вибору MQTT, CANly після підключення та узгодження набору сигналів видаляє його retained discovery-конфігурацію. Завдяки цьому Home Assistant не зберігає entities, які більше не вибрані для MQTT-телеметрії.

Під час публікації поточної discovery-конфігурації CANly також видаляє стару форму legacy discovery topic для цього сигналу.

!!! note "Примітка"
    Щоб автоматично оголошені sensor entities з'явилися в Home Assistant, MQTT Discovery має бути ввімкнений в інтеграції MQTT Home Assistant.

## Повторне підключення

Якщо MQTT-з'єднання втрачено, коли MQTT увімкнений **і зчитування все ще триває**, CANly автоматично планує повторні спроби підключення.

Поточні затримки:

```text
1 с → 2 с → 5 с → 10 с → 15 с
```

Наступні спроби продовжуються з інтервалом 15 секунд, доки сеанс зчитування не буде зупинено, MQTT не буде вимкнено або з'єднання не відновиться.

Після повторного підключення стан доступності повертається до `online`, поточний snapshot вибраної телеметрії може бути опублікований знову, а Home Assistant discovery узгоджується з поточним вибором.

## Стан на головному екрані

Головний екран показує стан MQTT. Реалізація розрізняє вимкнений/зупинений стан, підключення, успішне підключення та помилку.

MQTT працює незалежно від журналювання зчитування. **Журнал** записує файли, а **MQTT** публікує live-телеметрію.

## Усунення проблем

Якщо MQTT не підключається, перевірте host, port, облікові дані та TLS у **Налаштуваннях**, а також доступ Android-пристрою до broker.

Якщо в Home Assistant не з'являються entities, спочатку переконайтеся, що PROJECT YFA підключений до broker і справді отримує декодовані значення сигналів. Discovery створюється з фактично отриманої телеметрії.

MQTT має власне діагностичне журналювання в реалізації програми. Параметри broker і зберігання пароля описано на сторінці **Налаштування**.

# Усунення несправностей

Починайте пошук проблеми за повним шляхом даних:

**Android-пристрій → вибраний транспорт → адаптер → CAN-шина автомобіля → ECU → декодер / журнал / MQTT**

Працюйте з підключенням, коли автомобіль нерухомий.

## USB-адаптер не визначається

Переконайтеся, що в **Налаштування → Підключення → Адаптер** вибрано **USB CANnectivity**.

Від'єднайте та знову підключіть адаптер. Android може показати запит дозволу USB; без цього дозволу PROJECT YFA не може відкрити пристрій.

Успішне USB-підключення та активний сеанс CAN-зчитування — це різні стани. Якщо адаптер підключається, але даних немає, перевірте також вибраний ECU, режим зчитування та налаштування сигналів.

## Raw CAN не має даних

Перевірте, що для вибраного ECU ввімкнено хоча б одну RAW CAN-групу та хоча б один сигнал вибрано для LIVE або PLOT.

Raw CAN через USB працює в listen-only. Якщо незалежний CAN-логер також не бачить очікуваного трафіку, причина може бути поза PROJECT YFA — наприклад, ECU зараз не передає це повідомлення.

## Пасивний UDS не має даних

Пасивний UDS не надсилає діагностичних запитів. Він може декодувати лише вибрані відповіді ECU, які вже присутні в шині.

Якщо інший тестер або інша діагностична активність не створює цих відповідей, порожній екран Пасивного UDS може бути очікуваним. Використовуйте Активний UDS, коли PROJECT YFA має сам запитувати дані.

## CAN приймається, але Активний UDS не працює

Приймання звичайного CAN-трафіку підтверджує лише RX-частину шляху.

Активному UDS додатково потрібні USB bulk OUT/TX, передавання CAN, правильні діагностичні TX/RX ID та ECU, який активний і здатний відповісти.

Прошивка Waveshare для PROJECT YFA використовує окремі RX і TX пули gs_usb саме для того, щоб безперервний RX-трафік не міг позбавити діагностичний TX буферів. Подробиці наведено на сторінці **Waveshare RP2350-CAN**.

Якщо є незалежний CAN-логер, порівняйте його запис із debug log PROJECT YFA: перевірте, чи діагностичний запит справді з'явився в CAN-шині автомобіля та чи ECU сформував відповідь.

## Проблеми після перепідключення USB

Перед навмисним від'єднанням адаптера зупиніть зчитування.

Після повторного підключення надайте дозвіл USB, якщо Android його запитає, підключіться в PROJECT YFA і лише тоді запускайте зчитування. Фізичне від'єднання USB виявляється програмою та закриває активний USB-транспорт.

Для дослідження періодичної USB-проблеми перед її відтворенням увімкніть **Налаштування → Запис → Діагностичний журнал адаптера**.

## Сигнал відсутній у Live

Відкрийте **Сигнали** для вибраного ECU.

Перевірте, що для вибраного режиму зчитування доступна правильна RAW- або UDS-група та для сигналу встановлено **LIVE**. Сигнал, вибраний лише для **PLOT**, зчитується для графіка, але навмисно не займає місце в таблиці Live.

Якщо визначення сигналу додано в новішій версії бази, PROJECT YFA узгоджує збережені налаштування з вбудованою базою та автоматично додає нові визначення.

## Plot порожній

Для сигналу потрібно вибрати **PLOT** у редакторі Сигнали до того, як він потрапить в історію графіка.

LIVE і PLOT — незалежні параметри: увімкнення LIVE саме по собі не вмикає побудову графіка.

## Журнал не запускається

Виберіть каталог із правом запису в **Налаштування → Запис → Каталог журналів**.

Якщо журналювання ввімкнено, але каталог не налаштований, PROJECT YFA може попросити вибрати його під час запуску зчитування. Якщо доступ до раніше вибраного каталогу втрачено, виберіть його знову.

## Екран Журнали порожній

Екран Журнали розпізнає `.TXT` журнали PROJECT YFA у вибраному каталозі. Окремий індекс не ведеться.

Переконайтеся, що вибрано правильний каталог і він містить файли із заголовком PROJECT YFA. Сторонні TXT-файли ігноруються.

## Не працює експорт CSV

Поточний CSV-експортер декодує підтримувані **UDS LIVE** відповіді за допомогою вбудованої бази сигналів.

Тому коректний сирий журнал може містити корисний трафік, але не мати відповідей, придатних для поточного CSV-експортера. У такому разі PROJECT YFA повідомляє, що live-відповідей сигналів не знайдено.

## Не працює Інформація ECU

**Інформація ECU** виконує активні одноразові діагностичні запити. Вона доступна лише за наявності підключення та коли звичайне зчитування не працює.

Частина запитів ідентифікації може завершитися помилкою, а інші значення все одно будуть показані. Якщо для ECU взагалі немає визначень ідентифікації, PROJECT YFA повідомляє про це.

## MQTT не підключається

Перевірте **Налаштування → Підключення → MQTT broker**: host, port, облікові дані, base topic і TLS.

Також переконайтеся, що Android-пристрій має мережевий доступ до broker. Якщо з'єднання втрачено, поки MQTT залишається ввімкненим, PROJECT YFA автоматично повторює спроби.

## У Home Assistant не з'являються entities

PROJECT YFA публікує Home Assistant MQTT Discovery лише для сигналів телеметрії, які фактично отримує.

Переконайтеся, що MQTT підключений, зчитування дає декодовані значення, а MQTT Discovery увімкнений в інтеграції MQTT Home Assistant.

## Дані для налагодження

Для періодичних проблем транспорту збережіть відповідний debug log PROJECT YFA та, якщо можливо, одночасний запис незалежного CAN-логера.

Зіставлення подій програми з трафіком шини особливо корисне, щоб відрізнити:

- проблеми транспорту Android/USB;
- проблеми TX/RX адаптера;
- запити, які потрапили в CAN-шину, але не отримали відповіді ECU;
- відповіді, присутні в шині, але не оброблені програмою.

Сторінки **USB CAN-адаптер**, **Журнали** та **MQTT і Home Assistant** містять детальнішу інформацію про відповідні підсистеми.
